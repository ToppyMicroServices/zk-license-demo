# 実カード・本人確認の接続境界

2026-10-17。今回追加したのは発行側の実験用コンポーネントであり、実カードの読み取りや
公的な本人確認サービスとの接続を完了したものではない。公開Webデモと既存の模擬発行処理は変更していない。

## 実装した部分

`card_signature.py` は、運用者が登録したRSA公開鍵で、指定したカード領域の署名を検証する。
カードから受け取った鍵や `verified: true` は信用しない。署名対象は
従来IC免許証の `DF1/EF01`・`DF1/EF02`・`DF2/EF01`、またはマイナ免許証の `WEF02` に限定する。
それ以外の追記情報の真正性や、記載内容の意味を確認する処理ではない。

`enrollment_gate.py` は、読み取りアダプター、署名検証、本人確認アダプターを順に呼ぶ。
同意、利用者のアカウント、ウォレットの発行要求、確認先、期限を同じ申込みに結び付ける。
別のカード・ウォレット・認証結果への差し替えを拒否し、完了した申込みは再利用できない。
実験用のローカル受付記録を返すだけで、資格情報の発行や運転の許可は行わない。

初期状態では読み取り・本人確認アダプターも、公的な検証鍵も設定されていない。
未設定のまま成功する代替処理はない。最新の停止・取消し確認は常に未実施として扱う。

## 署名形式は実カードとの照合が必要

[警察庁仕様書](https://www.npa.go.jp/laws/notification/koutuu/menkyo/menkyo20240719_145.pdf)
のPDF 17・34ページは、RSA2048、SHA-256、PKCS#1 v1.5を記載している。
一方、図はDigestInfoを挟まずSHA-256の値を置く形になっている。
一般的な `RSA/SHA-256` の検証APIがそのまま使えると判断しない。

今回の実験モードは図に合わせた `npa-rsa2048-pkcs1v15-raw-sha256-experimental` のみ。
[cryptography 49のRSA機能](https://cryptography.io/en/49.0.0/hazmat/primitives/asymmetric/rsa/)
で検証し、独自のRSA演算やパディング処理は実装していない。
別方式への自動フォールバックはない。
署名対象領域は図の長さを厳密に要求する。短いデータへの推測によるゼロ埋めや再符号化は行わない。
この形式・領域の扱いは、許可された試験カードや提供元の検証例との照合が済むまで実カード互換とは扱わない。

## 接続先に求める契約

読み取り側の `CardReader.read(context)` は、正式なSDKまたは読取り処理から
`CardCapture` を返す。PINの入力・カードアクセス・署名領域の取得はこのアダプターの責任であり、
今回まだ実装していない。PIN・カード画像・元データをログへ出力しない。
保存済みの署名付きデータを再生しても署名検証は通るため、この部品だけで現物所持や新しい読取りは証明できない。

本人確認側の `IdentityAdapter.verify_and_match(context, record, signed_files)` は、
次の確認を完了した後にだけ `BoundIdentity` を返す。

- 提供元のプロトコルに従った認証と、署名・発行元・宛先・nonce・時刻等の検証。
- その本人と、渡された署名検証済みの免許情報との結び付け。
- 当該申込み、ウォレット要求、同意への結び付け。

本人との照合には、ゲートが署名検証に使った同じバイト列の変更不能なスナップショットを渡す。
別途クライアントが送った氏名・生年月日などを免許証の確定情報として使わない。
文字変換・旧姓・外字・属性不足の扱いは提供元の仕様を確認して決め、曖昧な一致を自動承認しない。
今回のテスト用アダプターは本人照合を実証しない。

公開HTTP受付やOIDCクライアントはまだない。実接続には、BFFでの認証、トークン検証、
PKCE/state、秘密鍵・アクセストークン管理、提供元のタイムアウト、回復手順が必要になる。
ゲートのアカウントIDは、認証済みバックエンドから渡す前提であり、ブラウザー入力を本人確認済みとは扱わない。
受付記録はローカル監査用で、外部から提出できる認可トークンではない。
後続の実発行は未接続であり、発行処理まで含めた原子性・再送対策も別途検証する。

## ローカル検証

隔離した環境で追加依存を導入する。既存デモだけなら従来の `requirements.txt` を引き続き利用できる。
追加の固定ハッシュは、CPython 3.12のUbuntu/Windowsと3.14のmacOS arm64向け。

```bash
python -m pip install --require-hashes -r requirements-ingestion.txt
REQUIRE_CRYPTO=1 REQUIRE_CARD_CRYPTO=1 python -W error -m unittest discover -s tests -v
```

テストは生成したRSA鍵と架空のカード領域を使う。署名改ざん、別鍵、署名方式の混同、
本人確認結果の差し替え、拒否、期限切れ、再送、並行処理を検査する。
実カード、公式検証鍵、読み取りSDK、デジタル認証サービス、警察の処分情報は使っていない。
macOS・Ubuntu・Windowsでの実行結果と対象コミットは[検証記録](ingestion-validation.md)に残す。

## 次の接続判断

1. 読み取りSDKの評価・組み込み条件と、検証鍵の取得・更新責任を確定する。
2. デジタル認証サービス等の試験利用条件を満たし、登録情報と許可された試験環境を得る。
3. 許可されたカードで、署名形式・デコード・本人との結び付けを照合する。

取得先・条件の調査と未送信の質問は[実連携メモ](real-license-integration.md)に記録する。
