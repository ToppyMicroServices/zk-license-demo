# UI基準

対象は利用者が画面で読む文言と、その見た目。内部の識別子や技術文書の用語は対象外。

- **見出しは内容を示す。** 「共有内容の確認」のように短く名付ける。操作の呼びかけや宣伝文にしない。結果・待機状態は「証明を送信しました」のような文でもよい。
- **ボタンは操作を示す。** 「同意して共有する」「今回は共有しない」のように、押した結果がわかる言葉にする。説明文は自然な「です・ます」で書き、無理に名詞へ縮めない。
- **承認済みの表記を使う。** 下表を基準とし、同じ対象に別名を付けない。

  | 対象 | 表記 |
  | --- | --- |
  | 利用者のアプリ | Wallet |
  | 条件を確かめる側 | 受付 |
  | 受付から届く依頼 | 確認内容 |
  | 共有を選ぶ画面の見出し | 共有内容の確認 |

- **利用者の判断に必要な情報を先に置く。** 送信先・条件・共有範囲を明示する。制度・組織・暗号の専門語を主画面の役割名に使わず、必要な技術説明は詳細へ置く。
- **実際の状態を書く。** 作成・送信・受信・確認完了を区別し、未確認の到着や成功を断定しない。サンプルであることと実免許証・本人確認には使えないことを短く示す。非開示の項目を具体的に挙げ、完全匿名とは言わない。
- **エラーは次の操作まで書く。** 原因を断定できないときは断定せず、画面上で実行できるやり直し方を案内する。
- **既存のブランドを再利用する。** 3つの操作画面の背景・ロゴは `web/brand.css` と `web/toppy-logo.png` にそろえる。画面ごとに別の配色やロゴを作らない。
- **画面の流れで読み直す。** ログイン、待機、共有確認、処理中、結果、エラー、詳細を確認する。同じ語の反復、曖昧な主語、不要な説明を減らす。文言レビューと動作・表示の検証は別々に記録し、テスト成功を文章の自然さの根拠にしない。
