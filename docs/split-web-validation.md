# 分離Web画面の検証記録

2026-10-18（日本時間）。模擬データだけを使ったローカル検証。

| 対象 | 観測結果 |
| --- | --- |
| macOS / Python 3.14.6 | Web接続を追加した `84283c3` の実装で、`REQUIRE_CRYPTO=1`、警告をエラー扱いにして全96件成功。実行ログは[こちら](evidence/2026-10-18-split-web/tests-macos.log)（SHA-256 `c3430d7a2972dfd7005c90fa6a70917534f5cdeaac1441dea035a2a219151105`）。 |
| 分離WebのHTTP統合テスト | 新規10件成功。実AnonCredsで同意・拒否、認証境界、失効と再発行、鍵更新、再ペアリング、制限中のログアウト、検証中のセッション失効を確認。二つのサービスを実際の別プロセスで起動するテストを含む。 |
| JavaScript | `node --check split_web/verifier.js` と `node --check split_web/wallet.js` が成功。 |
| ローカルブラウザ | 検証者・ウォレット双方の画面表示と模擬ログイン、検証者での要求作成、ウォレットでのログアウトを操作確認。 |

使用したブラウザ操作環境では、検証者画面が開いたウォレットのポップアップを一覧から取得できなかった。
そのため、**実ブラウザでの画面間メッセージ、同意・拒否の終端表示は未確認**。
別プロセス間のAPIを通す同意・拒否は上記のHTTPテストで確認したが、画面操作の代わりとは扱わない。
Windows・UbuntuのCI結果はPRのチェックに記録する。

これはループバック上の模擬資格情報に対する検証であり、実免許証、実ユーザー、警察の状態照会や本番運用の検証ではない。

同日の画面文言の見直しでは、利用者向けの説明を「受付」「確認内容」「共有する／今回は共有しない」にそろえた。
サンプルデータの範囲と、証明に含めない免許情報・受付に伝わる識別子は引き続き表示する。
3本のJavaScriptの構文と、3画面のIDの重複・参照欠落を確認した。
ブラウザでは、分離版のログイン表示・受付での確認開始、従来版の共有する／共有しない両方の終端表示を操作確認した。
分離版のポップアップを使う画面間通信の未確認範囲は上記のままである。

背景とロゴは、[Toppy の公開記事](https://www.toppymicros.com/zk-license-demo.html)で使う濃紺 `#02213b` と既存の画像ロゴにそろえた。
3画面は同じ `web/brand.css` と `web/toppy-logo.png` をローカル配信し、表示時に外部サイトへ画像やフォントを取得しない。
ロゴは既存サイトの `216722720.png` を無加工で再利用した（SHA-256 `00d83bad154078750b5c2b3efa0ce2586905dfab3142a93cda9e7164e68ed7c5`）。
見出しは「共有する内容を確認する」とし、画面上の表記を `Wallet` に統一した。
3画面の背景・ロゴ・文言はデスクトップのブラウザで表示確認した。
共通アセットの配信、画像MIME、画像を同一originに限るCSP、許可されていないパスの拒否を含めて、macOSで全96件が成功した。
