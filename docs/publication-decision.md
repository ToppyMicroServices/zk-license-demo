# LinkedIn掲載判断メモ

作成日: 2026-10-04

## 判断

一般向けの「データを預からない設計を、読めるコードで示す」投稿には条件付きで掲載価値がある。
「Toppyが新しい本人確認技術を発明した」という告知には向かない。
**コードは公開済み。** macOSとLinuxのCIで全46テストと実証明の検証が通過し、公開GitHub URLも確認した。
LinkedInにはまだ投稿していない。投稿案の使用は、実際に投稿する文面と宛先の確認後とする。
一般向けの説明と保持・管理の提案は[日本語](press-ja.md)と[English](press-en.md)にまとめた。
公式サイトにも[日本語](https://www.toppymicros.com/zk-license-demo.html)と[English](https://www.toppymicros.com/zk-license-demo-en.html)の記事を公開した。
ブランド向上の効果は推測であり、測定した事実ではない。

## 新規性と読者にとっての新しさ

ZKを使って署名された本人確認属性を非開示で扱うアイデアには、AnonCreds、Longfellow、ZKPassportなどの先行例がある。
「まだほとんど誰も実装していない」とは言えない。
一般層の認知度は今回測定していないため、「多くの人が知らない」とも断定しない。
根拠: [sources.md](sources.md)。

独自性は暗号方式ではなく、公開データの範囲と拒否条件を同時に確認できる、小さく再現可能な説明用実装に限定する。
これは新規研究の主張ではなく、実装と説明の質を示す成果物として扱う。

## 掲載する条件

1. hash固定した実ライブラリで、全46テストが通ること。30の単体テストだけでは足りない。
2. 証明生成・独立検証・再送拒否を再現でき、実測環境と測定範囲が残ること。
3. 一般の読者がアクセスできるGitHub URLが実在し、READMEと実コード・テストが一致すること。
4. 所有者が文面を確認し、「実免許証対応」「免停確認」「侵入防止」「完全匿名」「今回の被害を防げた」などの誤解がないこと。

投稿では報道を1文程度の入口にとどめ、被害者の不安を煽らず、特定社への根拠のない批判もしない。
模擬発行者・模擬資格情報を使用していることを短く明示する。

## 掲載後の評価案（未実施）

単純な表示回数より、実装や導入条件についての具体的な質問、READMEへの遷移、再現報告を確認する。
これらも直接のブランド向上と同一ではなく、読者が技術内容を評価したかを見る補助指標とする。
